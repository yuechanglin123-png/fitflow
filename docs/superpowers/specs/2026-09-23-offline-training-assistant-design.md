# 训练中端侧语音助教设计规格

日期：2026-09-23

状态：用户已认可方案；本文待用户审阅。尚未实施或验证模型。

## 1. 目标与已确认范围

为现有原生 Android 力量训练 App 添加可随时开启、关闭的语音助教。用户可以在训练时免手动执行四类操作，获得休息提醒和鼓励，并询问时间、天气和训练进度。中文识别与播报在设备运行，实时天气通过网络获取。

用户已选择：先说唤醒词再说指令；手动设置默认天气城市，也可以在问题中指定城市；采用轻量离线语音模型和确定性指令处理。首版问答覆盖明确范围，不承诺自由聊天。APK、安装后的应用及模型静态文件占用分别验收，均不超过 500,000,000 字节；运行内存另行测量，不能用 APK 大小替代。

## 2. 页面与交互

- 训练中页面增加“AI 助教”开关、男声/女声选择和默认城市设置入口。
- 首次开启申请麦克风权限，解释用于本地语音识别。拒绝权限时开关保持关闭，其他训练操作正常可用。
- 展示“正在初始化”“等待唤醒”“请说指令”“正在处理”“正在播报”和明确的错误状态；显示最近一次识别文字及执行结果。
- 默认唤醒词为“小练小练”。支持一句话“小练小练，完成本组”，也支持先唤醒、提示音后再说指令。
- 唤醒后等待最长 8 秒；无有效语音则回到等待唤醒。只处理完整识别结果，不依据中间结果改变训练状态。
- 每次唤醒最多执行一个操作，执行后返回等待唤醒。去重采用识别回合 ID，防止同一识别结果重复回调造成多次完成或延长。
- 播报期间暂停识别，播放完成后清空录音缓冲再恢复，防止回声触发自身指令。
- 关闭开关立即停止录音、识别、待播报任务及当前播报；网络请求取消，迟到回调不得重新启动助教。
- 音色和城市本地保存。应用重启后不自动打开麦克风；同一进程内返回训练页保留用户选择。

## 3. 训练指令与状态约束

语音和按钮使用同一 SessionViewModel/SessionReducer 操作入口，保持现有组间休息、动作间休息和暂停语义。提交操作前在同一状态锁内重新检查会话 ID、阶段和当前小组，防止识别延迟作用到新的训练组。

| 指令 | 可以执行的状态 | 操作与回应 |
| --- | --- | --- |
| 跳过休息 | 正在休息、未暂停 | 调用 skipRest，提示下一组已就绪 |
| 延长30秒休息时间 | 正在休息、未暂停 | 调用 extendRest(30)，提示已延长30秒 |
| 暂停训练 | 未结束、未暂停 | 调用 pause，提示训练已暂停 |
| 完成本组 | 当前组就绪、未暂停 | 调用 completeSet，播报实际结果：组间休息、动作间休息或训练完成 |

支持“三十秒”“加三十秒”“这组完成了”等明确同义表达；否定句、冲突指令和不明确结果不执行，提示重说。暂停期间仍可唤醒查询，但四类操作遵守上表；恢复训练使用已有按钮。已经暂停时再次要求暂停只提示当前状态。

## 4. 主动提醒

### 休息即将结束

- 组间休息和动作间休息都在剩余时间首次进入 0～10 秒区间（不含 0）时提醒准备；短于10秒的休息开始后提醒一次，0秒休息不提醒。
- 每个休息阶段仅提醒一次。延长休息后若剩余时间重新超过10秒，允许新截止时间前再次提醒；暂停、恢复本身不重复提醒。
- 跳过、结束或暂停后取消对应排队播报；播报前再次检查阶段、截止时间及会话是否仍有效。

### 每10分钟鼓励

- 从训练开始累计未暂停时间，包含组间与动作间休息。暂停时冻结；关闭助教不改变训练计时。
- 每跨过一个10分钟节点，助教开启时播报一次简短鼓励；开启时不补播之前错过的节点。
- 语音指令回应和休息准备提醒优先，鼓励可推迟最多30秒，随后丢弃，避免叠加播报。
- 累计时长及已处理节点随训练快照保存，兼容旧记录缺省值，恢复记录时不产生鼓励连播。

## 5. 简单问答与天气

- 本地回答：当前时间、日期、当前动作、当前组/剩余组数、剩余休息时间。数据取设备时区和实时训练快照。
- 天气优先采用问题中明确的城市，否则使用默认城市。默认城市通过搜索后选择城市及地区并保存坐标，避免同名城市误选。
- 无默认城市时提示先设置城市；语音指定城市出现多个匹配时提示到界面选择，不擅自采用其他地区。
- 首版天气回答城市、天气描述、气温和今日最高/最低温。采用具有可核验使用条款的天气与城市地理编码服务，优先评估 Open-Meteo；接口适用范围和归属说明须在接入时核对。
- 网络请求设超时；无网、超时或无结果时明确告知天气暂不可用，不编造实时数据。网络仅传城市查询或坐标，不上传录音、识别全文或训练记录。
- 超出首版范围时说明可以询问的内容，不让不受控生成结果直接操作训练。

## 6. 模型方案与体积预算

候选识别模型为 Vosk Small CN 0.22（官方公布下载体积约42MB，Apache-2.0），候选本地合成为 sherpa-onnx 支持的中文多说话人 VITS/AISHELL3。它们是语音模型，指令匹配由应用负责。

模型落地必须通过以下选择门槛：

1. 核对运行库及具体权重的许可证、再分发条件，保留必需的声明；不能以运行库开源推定所有权重可自由再分发。
2. 下载实际文件并记录版本、来源、校验值、压缩及解压大小。公开文档中体积口径不一致时以交付文件为准。
3. 识别候选模型先验证中文唤醒词、四类命令及城市查询；不达标再评估 sherpa-onnx 中文识别候选，仍遵守总预算。
4. 合成候选需试听并选择可区分的普通话男声和女声，不用简单改变音调冒充两个音色。
5. 优先支持 arm64 Android 手机（现有 minSdk 26）；模拟器运行库作为测试产物管理。交付时明确 APK 架构适用范围。

目标静态预算：现有应用及运行库80MB、识别及唤醒相关文件150MB、语音合成及词典150MB，预留120MB。此预算是设计上限，不是已经测得的包体大小。

模型随 APK 提供，首次运行无需下载。资源尽量直接读取或只保留必要的工作副本；验收时计入 APK 内嵌资源、已解压副本及持久缓存，不能只统计压缩模型。

- https://alphacephei.com/vosk/models
- https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html
- https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/rtf.html

## 7. 生命周期与结构

- AssistantController：持有开关、唤醒回合、命令解析和播报队列；用会话代次隔离过期异步结果。
- SpeechRecognizerAdapter / SpeechSynthesizerAdapter：封装本地推理及释放，便于替换模型和测试。
- AssistantCommandDispatcher：将已解析指令交给训练状态入口，返回实际执行结果。
- AssistantReminderPolicy：依据训练状态及时间生成可去重的提醒事件。
- WeatherRepository：负责城市搜索、天气接口、超时及错误转换。
- AssistantSettings：本地保存音色、默认城市；不保存录音。

用户在可见训练界面开启后，使用符合目标 Android 版本要求的麦克风前台服务，支持锁屏期间监听与提醒，通知提供“关闭助教”。与现有训练前台服务协调音频和计时所有权，避免重复提醒。

来电、音频焦点丢失、麦克风被占用或权限撤销时停止录音/播报并明确显示状态。训练结束、用户关闭或服务销毁时释放模型和音频资源。系统终止进程后不自行重新打开麦克风。音频路由遵循系统当前选择；蓝牙耳机兼容情况必须实测并记录。

## 8. 验证与交付标准

- 自动化验证：四类命令及同义句、否定句、阶段限制、重复回调、会话切换、暂停与恢复、提前提醒和每10分钟节点、不补播、天气异常。
- 界面验证：权限拒绝与撤销、开关随时关闭、音色保存、城市选择、操作结果显示；原有训练、暂停修改和预设回归通过。
- 用真实模型处理中文测试录音，覆盖两种声音、四类指令、唤醒与未唤醒、时间及城市查询；业务假实现测试不能替代模型验证。
- 小规模验收录音集：至少40条清晰指令/问句，完整意图正确率目标不低于90%；至少20条背景/非指令样本不得执行训练操作。报告样本来源与实际结果，不能据此宣称所有健身房环境均可可靠识别。
- 测量唤醒响应、指令结束到执行、播报首音延迟、模型初始化及内存峰值；分别记录测试设备。模拟器结果不能代替手机性能结论。
- 验证开启后锁屏、暂停、关闭、来电/音频抢占、离线模式和天气联网路径。无法在现有设备验证的部分列入真机验收项，不声称已通过。
- 最终检查 APK 可安装、包含所需模型和许可声明，APK 与安装后应用/模型静态占用均低于500MB；生成根目录新版 APK 并提供验证记录。

## 9. 实施顺序

先验证候选模型的许可、体积、识别和双音色效果，再接入训练命令及提醒，随后完成页面、后台生命周期和天气，最后完成集成测试与打包。模型未通过门槛时明确报告实测差距，不交付仅有界面的空功能。
